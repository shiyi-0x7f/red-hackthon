# 前后端对接问题全面诊断报告

经过逐行审计 `src/services/index.ts`（前端服务层）与 `server/app/routes/*.py`（后端路由）+ `server/app/schemas/*.py`（后端数据模型），我发现了 **18 个对接问题**，其中 **7 个是致命的 422/崩溃级别**。

## 🔴 致命问题（会导致 422 / 功能完全不可用）

### 问题 1：`submit_answer` 字段名不匹配 → 422 Validation Error

> [!CAUTION]
> 这是最核心的问题 —— 答题提交直接 422，整个学习闭环断裂。

| 字段 | 前端发送 (toSnakeCase后) | 后端 SubmitAnswerRequest 期望 |
|------|--------------------------|-------------------------------|
| 学生答案 | `answer` | `student_answer` ❌ |
| 提示次数 | `hints_used` | `hint_used` ❌ (静默丢失，默认0) |
| 学生ID | `student_id` (多余) | 不在schema中 (从session读) |

**根因**: 前端 `learningService.submitAnswer()` 传的参数名是 `answer`，经过 `toSnakeCase` 还是 `answer`，但后端 Pydantic 模型要求 `student_answer`。缺少必填字段 → **422**。

#### 修复

##### [MODIFY] [index.ts](file:///d:/SoftwareData/web/ai/ai_learning_back/.claude/worktrees/modest-rhodes/src/services/index.ts)
- `submitAnswer` 函数的 `answer` 参数名改为 `studentAnswer`（→ snake → `student_answer`）
- `hintsUsed` 改为 `hintUsed`（→ snake → `hint_used`）

### 问题 5：`interestService.delete` 参数传递错误

前端调用：
```ts
invoke<boolean>('delete_interest', { id })
```

HTTP_ROUTE_MAP 定义：
```ts
delete_interest: (a) => ({ method: 'DELETE', path: `/api/v1/interests/${a.interestId}` })
```

前端传的是 `{ id }`，但路由映射取的是 `a.interestId` → **`undefined`** → URL 变成 `/api/v1/interests/undefined`

#### 修复

##### [MODIFY] [index.ts](file:///d:/SoftwareData/web/ai/ai_learning_back/.claude/worktrees/modest-rhodes/src/services/index.ts)
```diff
- delete_interest: (a) => ({ method: 'DELETE', path: `/api/v1/interests/${a.interestId}` }),
+ delete_interest: (a) => ({ method: 'DELETE', path: `/api/v1/interests/${a.id}` }),
```

### 问题 7：`generate_quiz` 模式默认值不合理

```python
class QuizGenerateRequest(BaseModel):
    mode: str = "adaptive"  # 默认是 adaptive
```

前端不发送 `mode` 参数 → 后端默认用 `"adaptive"`。但对新用户（还没有 mastery_data），`adaptive_quiz({}, 5)` 可能返回空列表或不合理的题目。

**预期行为**：新用户应该走 `"auto"` 模式（按答题数量自动切换 diagnose → emerging → adaptive）。

#### 修复

##### [MODIFY] [question.py (schema)](file:///d:/SoftwareData/web/ai/ai_learning_back/.claude/worktrees/modest-rhodes/server/app/schemas/question.py)
```diff

+ mode: str = "auto"
```

### 问题 15：Learn 页直接 fetch 静态 JSON 而非走 API

```ts
// Learn/index.tsx:417
const resp = await fetch('/data/grade6_math_knowledge_map.json');
```

在生产环境 `learn.11xy.cn` 部署时，如果前端 dist 里不包含 `/data/` 目录，这个请求会 404。应该改为调用 `/api/v1/knowledge/tree?grade=6`。

### 问题 16：`interestService.add` body 里包含多余 `student_id`

前端 `invoke('add_interest', { studentId, category, name, affinity, notes })` 会在 body 里把 `student_id` 也发过去。 后端 `InterestCreate` schema 不含 `student_id`（从 URL path 取），Pydantic 默认忽略多余字段，不影响功能但不够干净。

---

### 问题 17：SSE 事件解析中的 `\r\n` 替换

```ts
// index.ts:340
buffer += decoder.decode(value, { stream: true }).replace(/\\r\\n/g, '\\n');
```

这里替换的是字面量 `\r\n` 字符串，而非真正的回车换行字符。应该是 `/\r\n/g`（无转义）。同样的问题在 Home/index.tsx:238 也存在。

> [!NOTE]
> 但由于 SSE 标准里 `\r\n` 和 `\n` 都是合法的行分隔符，`sse-starlette` 库发送的通常是 `\n`，所以实际上可能不会触发 bug。但在 Windows 环境或代理服务器修改了换行符时可能出问题。

---

### 问题 18：`HintRequest` schema 要求 `student_id` 但前端可能不传

后端 `HintRequest` 的 `student_id` 是必填 (`str`，无默认值)。前端 `hintService.get()` 的 `studentId` 和 `sessionId` 都是可选参数（`?`）。如果前端不传 `student_id`，后端会 422。
