# 技术栈与基础设施

> 本文档定义项目的技术选型、开发环境配置和项目结构。  
> 架构方案：**Tauri 2 桌面端 (React + Vite + Rust) + 硅基流动 LLM API**

```
┌──────────────────────────────────────────────────┐
│                Tauri 2 桌面应用                    │
│                                                  │
│  ┌──────────────┐     ┌───────────────────────┐  │
│  │  前端 (React)  │     │  Rust 核心 (Tauri Cmd) │  │
│  │  学习界面      │◄───►│  学生模型管理          │  │
│  │  对话交互      │     │  决策引擎              │  │
│  │  数学渲染      │     │  节奏控制              │  │
│  │  家长端视图    │     │  特征计算              │  │
│  │  图表可视化    │     │  SQLite 读写           │  │
│  └──────────────┘     │  API 调用代理          │  │

└──────────────────────────────────┼───────────────┘
                                   │ HTTPS
                 ┌─────────────────┼─────────────────┐
                 │                                   │
    ┌────────────┴────────────┐   ┌──────────────────┴──┐
    │  硅基流动 (SiliconFlow)   │   │   火山引擎 (Volcano)  │
    │                         │   │                      │
    │  • LLM（多模型可选）      │   │  • 流式语音识别 ASR    │
    │    DeepSeek-V3          │   │  • 语音合成 TTS       │
    │    Qwen2.5              │   │                      │
    │    GLM-4                │   │  （V2 阶段启用）       │

    └─────────────────────────┘   └──────────────────────┘
```

**核心思路**：
- **本地**：全部业务逻辑 + 数据存储 + UI → Tauri 2 (Rust + React)
- **云端 LLM**：硅基流动 API（多模型可选）
- **云端语音**：火山引擎 ASR/TTS（V2 阶段语音对话/抽背）
- **数据库**：SQLite 本地文件，零配置零运维
- **不使用 Sidecar**：所有后端逻辑用 Rust 原生实现

| **流式处理** | tokio-stream / SSE | LLM 流式响应 |

### 2.3 硅基流动 (SiliconFlow) API

硅基流动提供统一的 OpenAI 兼容接口，可按需切换多种开源模型：

| 模型 | 适用场景 | 说明 |
|------|---------|------|
| DeepSeek-V3 | 讲解/判题/复杂推理 | 数学能力强 |
| Qwen2.5-72B | 出题/问答 | 通用能力好 |
| GLM-4 | 对话/轻交互 | 中文对话流畅 |
| 其他模型 | 用户可自行配置 | 硅基流动支持的任意模型 |

**关键特性**：
- 兼容 OpenAI API 格式，切换模型只需改 model 参数
- 用户可在设置页面自选 LLM 模型
- 支持流式输出 (SSE)
- 按 token 计费，成本可控

### 2.4 火山引擎语音服务

| 服务 | 用途 | 阶段 |
|------|------|------|
| **流式语音识别 (ASR)** | 抽背语音转文字、语音输入答案 | V2 |
| **语音合成 (TTS)** | AI 朗读讲解、题目朗读（低年级） | V2 |

> 语音服务在 V2 阶段启用。MVP 阶段纯文字交互。

### 2.5 数据库

| 类型 | 技术 | 说明 |
|------|------|------|
| **主库** | SQLite 3 | 本地文件，一个用户一个 db 文件 |
| **全文搜索** | SQLite FTS5 | 知识检索、记忆召回 |
| **缓存** | 内存 (Rust HashMap/DashMap) | 学生实时状态 |
| **文件存储** | 本地文件系统 | 上传的书籍、音频 |

**为什么不需要向量数据库**：
- 行为特征是结构化数值，普通 SQL 列即可
- 知识检索用 FTS5 全文搜索足够
- V2 记忆召回时，Embedding 向量可存 SQLite BLOB 列，本地计算余弦相似度
- 单用户数据量小（几千条），不需要专门的向量索引

## 四、前后端通信方式

### Tauri Commands（核心）

前端通过 `invoke` 调用 Rust 函数，类似 RPC：

```typescript
// 前端调用
import { invoke } from '@tauri-apps/api/core';

// 获取学生画像
const profile = await invoke('get_student_profile', { studentId });

// 提交答案
const result = await invoke('submit_answer', {
    sessionId, taskId, answer, timeSpent
});
```

```rust
// Rust 端定义
#[tauri::command]
async fn get_student_profile(
    student_id: String,
    state: tauri::State<'_, AppState>,
) -> Result<StudentProfile, String> {
    let db = state.db.lock().unwrap();
    student_model::get_profile(&db, &student_id)
}
```

### 流式通信（LLM 流式输出）

使用 Tauri Events 实现流式推送：

```rust
// Rust: 流式调用 LLM，逐 token 推送给前端
#[tauri::command]
async fn stream_explain(
    app: tauri::AppHandle,
    params: ExplainParams,
) -> Result<(), String> {
    let stream = llm_client::stream_complete(&prompt).await?;
    while let Some(chunk) = stream.next().await {
        app.emit("llm-chunk", &chunk)?;
    }
    app.emit("llm-done", ())?;
    Ok(())
}
```

```typescript
// 前端: 监听流式事件
import { listen } from '@tauri-apps/api/event';

listen('llm-chunk', (event) => {
    appendToOutput(event.payload);
});
```

## 七、LLM 调用架构

### 7.1 统一 LLM 客户端

```rust
// ai/llm_client.rs
pub struct LLMClient {
    api_base: String,     // https://api.siliconflow.cn/v1
    api_key: String,
    model: String,        // 当前选择的模型
    client: reqwest::Client,
}

impl LLMClient {
    /// 普通完成（等全部生成完返回）
    pub async fn complete(&self, messages: &[Message], opts: &LLMOptions) -> Result<String>;

    /// 流式完成（逐 token 返回）
    pub async fn stream(&self, messages: &[Message]) -> Result<impl Stream<Item = String>>;

    /// 切换模型
    pub fn set_model(&mut self, model_id: &str);

    /// 获取可用模型列表
    pub fn available_models(&self) -> Vec<ModelInfo>;
}
```

> 硅基流动 API 兼容 OpenAI 格式，endpoint 为 `https://api.siliconflow.cn/v1/chat/completions`

### 7.2 成本控制

| 场景 | 策略 |
|------|------|
| 讲解复杂概念 | 全量模型 |
| 判题错因分析 | 全量模型 |
| 简单问答 | 轻量模型 / 缩短 prompt |
| 出题(模板化) | 规则优先，不够才调 LLM |
| 对话调节 | 轻量模型，短对话 |
| 缓存 | 相同知识点讲解缓存本地 |

## 九、家长端设计（MVP 简单版）

家长端作为**应用内独立视图**，密码保护访问：

```
应用内页面结构：
├── 学生端（默认）
│   ├── 学习
│   ├── 复习
│   ├── 休息区
│   └── 个人
└── 家长端（密码进入）
    ├── 学习概览（今日/本周学习时长、正确率）
    ├── 知识掌握（各知识点掌握进度条）
    ├── 使用健康（超时记录、休息情况）
    └── 设置（时长限制、密码修改）
```

**家长端原则**：
- 只展示汇总数据，不暴露原始对话内容
- 不展示标签化的特征分数
- 展示行为趋势（非单次数据）
- 提供可操作的建议（而非原始数字）
