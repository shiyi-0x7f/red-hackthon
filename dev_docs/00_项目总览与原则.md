# 项目总览与核心原则

> 本文档定义项目的产品定位、核心原则、系统总体架构和模块划分，是所有后续文档的基础。

---

## 一、产品定义

**一句话定义**：
> 一个以数学学习为主线、基于长期学生模型驱动教学决策的人机协作学习系统。

**产品名称**（待定）：AI 学习搭子 / 智学伙伴

**目标用户**：小学数学学习者（MVP 聚焦六年级）

**产品北极星**：
> "不是让学生离不开 AI，而是让学生在 AI 帮助下更能面对学习本身。"

---

## 二、核心差异（与市场产品对比）

| 维度 | 现有 AI 学习产品 | 本系统 |
|------|-----------------|--------|
| 记忆 | 会话级记忆，下次重来 | 长期学生模型，跨场景持续 |
| 个性化 | 只调难度 | 内容+方式+节奏+包装 全面个性化 |
| 过程 | 只看结果对错 | 采集过程数据，分析行为 |
| 状态 | 不感知学生状态 | 实时状态识别，动态调节 |
| 决策 | 推荐题目 | 控制整个学习过程 |
| 通道 | 单一入口 | Web + 飞书/微信 多通道统一 |
| 定位 | AI 工具 | 学习操作系统 |

## 三、三条铁律（不可违反）

### 1. 学习优先原则
> 一切模块（对话、游戏、宠物）服务于数学学习效果。

**判断标准**：如果关闭聊天功能，系统还能不能教得更好？  
→ 如果不能，说明走偏了。

### 2. 非诊断原则
> AI 不定义学生是什么样的人，只帮助学生看到自己正在做什么，以及可以如何做得更好。

**禁止输出**：
- 人格判断（内向、冲动等）
- 心理诊断（焦虑、抑郁等）
- 能力定性（你不行、你差）
- 绝对化结论（你总是、你从不）

**必须输出**：
- 行为描述
- 情境限定
- 可执行建议
- 正向引导

### 3. 反依赖原则
> 不制造情感依赖，只提供支持关系。

**判断标准**：用户留下来是因为"AI 很好聊"还是因为"我真的学得更好了"？  
→ 必须是后者。

## 四、产品两层本质

```
第一层（底座）：传统 AI 学习系统
├── 出题、题库、问答、讲解、判题、提示、复习、学习记录
└── 基础设施

第二层（差异化核心）：长期个性化决策系统
├── 学生模型（6 层画像）
├── 长时记忆（AstrBot 对话系统 + FAISS 向量检索）
├── 教学决策引擎
├── 节奏控制系统
├── 学习搭子式交互
└── 多通道统一（Web + 飞书 IM）
```

> 传统功能解决"能不能教"，差异化系统解决"怎么教得更适合这个学生"。

### 模块职责概览

| # | 模块 | 一句话职责 | 阶段 |
|---|------|----------|------|
| ⓪ | AstrBot 平台层 | 提供 LLM / IM / 插件 / 知识库基础设施 | MVP |
| ① | 内容资源层 | 提供可调用的教学内容 | MVP |
| ② | 基础学习功能层 | 出题、判题、问答的基础能力 | MVP |
| ③ | 学习主引擎 | 组织完整学习流程 | MVP |
| ④ | 学生模型 | 构建并持续更新 6 层画像 | MVP(简化) |
| ⑤ | 数据采集与特征层 | 把行为变成可建模数据 | MVP(基础)+V2 |
| ⑥ | 教学决策引擎 | 根据画像决定教学动作 | MVP(规则)+V2 |
| ⑦ | 节奏控制系统 | 控制时长、收束、休息 | MVP |
| ⑧ | 交互与陪伴层 | 对话调节、专属导师命令 | MVP |
| ⑨ | 可视化反馈层 | 仪表盘、知识图谱、学习报告 | MVP+V2 |

### 核心数据闭环

```
用户行为 → 数据采集 → 特征提取 → 学生模型更新 → 决策引擎 → 学习主引擎 → 交互反馈 → 用户新行为
```

## 六、三阶段开发总览

| 阶段 | 时间 | 核心目标 |
|------|------|---------
| **MVP** | 黑客松 48h | 验证"长期学生模型+教学决策 > 普通 AI Tutor" |
| **V2** | 第 2-4 月 | 增强观测能力，完善过程分析和兴趣建模 |
| **V3** | 第 5-8 月 | 高级自适应，多学科/多学段扩展 |

### MVP 范围（极简）

**必做**：
- 数学学习系统（出题+讲解+提示）— AstrBot LLM Provider
- 学生模型（知识层+行为层+状态层）— 扩展 AstrBot SQLite
- 决策引擎（规则版）— 新增 Python 服务
- 节奏控制 — 新增 Python 服务
- 专属导师命令（/start /goal /plan /checkin）— AstrBot 插件
- 可视化仪表盘 — Vue 前端扩展
- 飞书 + Web 双通道 — AstrBot 平台层

**不做**：
- 棋类 / 全能挑战 / 复杂宠物
- 阅读抽背
- 认知特征层
- 定时督学
- 多学段

## 七、学习搭子关系定义

### 正确定位
> 一个持续了解你学习情况、能一起思考、能适度交流、但始终以"帮助你变强"为目标的协作伙伴。

### 三层关系模型

| 层次 | AI 角色 | 负责 |
|------|---------|------|
| 工具层 | 讲解者/分析者 | 教会 |
| 协作层 | 一起思考的搭子 | 陪你做 |
| 轻社交层 | 可以聊几句的伙伴 | 让你愿意继续 |

> ⚠️ 绝不能出现第 4 层（情感依赖层）

### 互动风格原则

- 不抢主导权："我们可以一起试试"（非"我来教你"）
- 不替代思考：引导思路（非直接给答案）
- 不评判："这里有另一种更稳的方式"（非"你这样不对"）
- 不装懂人："听起来你刚刚有点卡住了"（非"我完全理解你"）

## 八、技术架构决策（已确认）

| 决策项 | 选择 | 说明 |
|--------|------|------|
| **应用形态** | AstrBot 深度改造 + Vue 前端 | C/S 架构，Web 优先 |
| **后端** | Python (AstrBot Quart Server) | 直接在 AstrBot 源码上扩展 |
| **前端** | Vue 3 + Vuetify (AstrBot Dashboard) | 扩展现有 Dashboard，新增学习页面 |
| **数据库** | SQLite (SQLModel ORM) | AstrBot 原生，新增学习系统表 |
| **LLM** | 硅基流动 (SiliconFlow) via AstrBot Provider | 复用 AstrBot 多模型管理 |
| **向量检索** | FAISS | AstrBot 原生知识库 |
| **IM 通道** | 飞书 + WebChat | AstrBot 平台适配器 |
| **模式切换** | AstrBot Persona 系统 | strict/gentle 两套人格 |
| **记忆系统** | 扩展 AstrBot 对话系统 | 不另建 memory.md |
| **插件系统** | AstrBot Star 插件 | 专属导师插件 |
| **认证** | AstrBot JWT + API Key | 复用现有认证 |
| **目标学段** | 小学六年级数学 | MVP 聚焦单年级 |
| **知识体系** | 人教版小学数学 | 六年级子集 |
| **语音服务** | 火山引擎 ASR/TTS | V2 阶段 |
| **团队** | 2 人（后端+前端 / AstrBot 插件） | 黑客松分工 |
