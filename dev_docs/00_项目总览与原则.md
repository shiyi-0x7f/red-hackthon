# 项目总览与核心原则

> 本文档定义项目的产品定位、核心原则、系统总体架构和模块划分，是所有后续文档的基础。

---

## 一、产品定义

**一句话定义**：
> 一个以数学学习为主线、基于长期学生模型驱动教学决策的人机协作学习系统。

**产品名称**（待定）：AI 学习搭子 / 智学伙伴

**目标用户**：小学～高中数学学习者

**产品北极星**：
> "不是让学生离不开 AI，而是让学生在 AI 帮助下更能面对学习本身。"

---

## 二、核心差异（与市场产品对比）

| 维度 | 现有 AI 学习产品 | 本系统 |
|------|-----------------|--------|
| 记忆 | 会话级记忆，下次重来 | 长期学生模型，跨场景持续 |
| 个性化 | 只调难度 | 内容+方式+节奏+包装 全面个性化 |
| 过程 | 只看结果对错 | 采集过程数据，分析行为 |
| 状态 | 不感知学生状态 | 实时状态识别，动态调节 |
| 决策 | 推荐题目 | 控制整个学习过程 |
| 定位 | AI 工具 | 学习操作系统 |

---

## 三、三条铁律（不可违反）

### 1. 学习优先原则
> 一切模块（对话、游戏、宠物）服务于数学学习效果。

**判断标准**：如果关闭聊天功能，系统还能不能教得更好？  
→ 如果不能，说明走偏了。

### 2. 非诊断原则
> AI 不定义学生是什么样的人，只帮助学生看到自己正在做什么，以及可以如何做得更好。

**禁止输出**：
- 人格判断（内向、冲动等）
- 心理诊断（焦虑、抑郁等）
- 能力定性（你不行、你差）
- 绝对化结论（你总是、你从不）

**必须输出**：
- 行为描述
- 情境限定
- 可执行建议
- 正向引导

### 3. 反依赖原则
> 不制造情感依赖，只提供支持关系。

**判断标准**：用户留下来是因为"AI 很好聊"还是因为"我真的学得更好了"？  
→ 必须是后者。

## 四、产品两层本质

```
第一层（底座）：传统 AI 学习系统
├── 出题、题库、问答、讲解、判题、提示、复习、学习记录
└── 基础设施

第二层（差异化核心）：长期个性化决策系统
├── 学生模型（6 层画像）
├── 长时记忆（4 层记忆体系）
├── 教学决策引擎
├── 节奏控制系统
├── 学习搭子式交互
└── 多场景数据融合
```

> 传统功能解决"能不能教"，差异化系统解决"怎么教得更适合这个学生"。

## 五、系统总体架构（9 大模块）

```
┌─────────────────────────────────────────────────────────────┐
│                    体验层                                    │
│  ⑦ 节奏控制系统  │  ⑧ 交互与陪伴层  │  ⑨ 可视化反馈层     │
├─────────────────────────────────────────────────────────────┤
│                    学习引擎层                                │
│              ③ 学习主引擎（任务编排 / 路径推进）               │
├─────────────────────────────────────────────────────────────┤
│                    智能中枢层                                │
│  ④ 学生模型  │  ⑤ 数据采集与特征层  │  ⑥ 教学决策引擎       │
├─────────────────────────────────────────────────────────────┤
│                    基础能力层                                │
│              ② 基础学习功能（出题 / 判题 / 问答）             │
├─────────────────────────────────────────────────────────────┤
│                    资源层                                    │
│        ① 内容资源层（知识图谱 / 题库 / 讲解库）               │
└─────────────────────────────────────────────────────────────┘
```

### 模块职责概览

| # | 模块 | 一句话职责 | 阶段 |
|---|------|----------|------|
| ① | 内容资源层 | 提供可调用的教学内容 | MVP |
| ② | 基础学习功能层 | 出题、判题、问答的基础能力 | MVP |
| ③ | 学习主引擎 | 组织完整学习流程 | MVP |
| ④ | 学生模型 | 构建并持续更新 6 层画像 | MVP(简化) |
| ⑤ | 数据采集与特征层 | 把行为变成可建模数据 | MVP(基础)+V2 |
| ⑥ | 教学决策引擎 | 根据画像决定教学动作 | MVP(规则)+V2 |
| ⑦ | 节奏控制系统 | 控制时长、收束、休息 | MVP |
| ⑧ | 交互与陪伴层 | 对话调节、阅读抽背 | MVP(轻量)+V2 |
| ⑨ | 可视化反馈层 | Live2D 抽象体、宠物 | V2+V3 |

### 核心数据闭环

```
用户行为 → 数据采集 → 特征提取 → 学生模型更新 → 决策引擎 → 学习主引擎 → 交互反馈 → 用户新行为
```

## 六、三阶段开发总览

| 阶段 | 时间 | 核心目标 |
|------|------|---------|
| **MVP** | 第 1-3 月 | 验证"长期学生模型+教学决策 > 普通AI Tutor" |
| **V2** | 第 4-6 月 | 增强观测能力，完善过程分析和兴趣建模 |
| **V3** | 第 7-12 月 | 高级自适应，棋类/挑战/宠物/家长端 |

### MVP 范围（极简）

**必做**：
- 数学学习系统（出题+讲解+提示）
- 学生模型（知识层+行为层+状态层）
- 决策引擎（规则版）
- 节奏控制
- 轻量对话
- 简单家长端（应用内密码保护视图）

**不做**：
- 棋类
- 全能挑战
- 复杂宠物
- 复杂心理建模

## 七、学习搭子关系定义

### 正确定位
> 一个持续了解你学习情况、能一起思考、能适度交流、但始终以"帮助你变强"为目标的协作伙伴。

### 三层关系模型

| 层次 | AI 角色 | 负责 |
|------|---------|------|
| 工具层 | 讲解者/分析者 | 教会 |
| 协作层 | 一起思考的搭子 | 陪你做 |
| 轻社交层 | 可以聊几句的伙伴 | 让你愿意继续 |

> ⚠️ 绝不能出现第 4 层（情感依赖层）

### 互动风格原则

- 不抢主导权："我们可以一起试试"（非"我来教你"）
- 不替代思考：引导思路（非直接给答案）
- 不评判："这里有另一种更稳的方式"（非"你这样不对"）
- 不装懂人："听起来你刚刚有点卡住了"（非"我完全理解你"）

## 八、技术架构决策（已确认）

| 决策项 | 选择 | 说明 |
|--------|------|------|
| **应用形态** | Tauri 2 桌面端 | 本地优先，零运维，隐私合规 |
| **后端** | Rust 原生 (Tauri Commands) | 不使用 Sidecar，全部逻辑用 Rust 实现 |
| **前端** | React + Vite (WebView) | 生态成熟，开发效率高 |
| **数据库** | SQLite 本地文件 | 零配置，单用户足够 |
| **LLM** | 硅基流动 (SiliconFlow) API | 支持多模型可选，用户可自行配置模型 |
| **语音服务** | 火山引擎 ASR/TTS | V2 阶段语音对话/抽背 |
| **向量数据库** | ❌ 不需要 | 行为特征用普通列，V2 记忆召回用 FTS5 |
| **目标学段** | 小学 (1-6年级) | MVP 聚焦人教版小学数学 |
| **知识体系** | 人教版小学数学 | 有成熟题库可用 |
| **目标平台** | Windows | 暂不考虑 Mac/Linux |
| **团队** | 开发者即教研老师 | 教研内容自建，无需额外教研团队 |
| **家长端** | MVP 阶段做简单版 | 应用内独立视图（密码保护） |
